# RushFinder 0930 — تطبیق راش YouTube با متن نریشن

در نسخه قبلی تابع searchQuery فقط یک کلیدواژه عمومی مثل economy می‌ساخت و حتی نتایج دارای امتیاز ارتباط صفر را هم در تایم‌لاین قرار می‌داد. در این نسخه:

- متن کامل نریشن تا ۱۲ بخش موضوعی تقسیم می‌شود؛ دیگر انتهای متن به‌خاطر سقف ۲۰ جمله حذف نمی‌شود.
- در صورت وجود OPENAI_API_KEY یا OPENROUTER_API_KEY، سرور دو مرحله تطبیق معنایی انجام می‌دهد: ۱) ساخت عبارت جست‌وجوی دقیق انگلیسی برای هر بخش، ۲) بررسی ارتباط عنوان/توضیحات ویدئوها با متن همان بخش.
- در نبود هوش مصنوعی، فیلتر سخت‌گیرانه محلی فعال می‌شود؛ نتیجه‌ای که مطمئناً مرتبط نیست وارد تایم‌لاین نمی‌شود.
- بخش‌های بدون راش مناسب با کادر هشدار خالی می‌مانند تا ویدئوی نامربوط به خبر نسبت داده نشود.
- روی هر کات علاوه بر عنوان منبع، متن مربوط به نریشن نوشته می‌شود.
- فقط YouTube جست‌وجو می‌شود و YOUTUBE_SMARTEDIT_API_KEY تغییری نمی‌کند؛ هیچ تابع سروری جدیدی اضافه نمی‌شود (۱۲ تابع).

## نصب
فایل‌های `smart-edit.html` و `smart-youtube.js` در ریشه GitHub و `api/youtube-music.js` در پوشه api جایگزین شوند. پس از Commit و Ready شدن Vercel با Ctrl+F5 صفحه تازه شود.

## محدودیت بسیار مهم
این نسخه **خود تصویر ویدئوی یوتیوب یا صدای آن را تحلیل نمی‌کند**: فقط متن نریشن و متادیتای ویدئو را بررسی می‌کند. برش‌های مجازی YouTube فایل قابل دانلود یا MP4 نیستند. زمان هر قسمت از روی تعداد کلمه و طول فایل نریشن *تخمینی* است؛ هم‌ترازی دقیق جمله با زمان صوت نیاز به تبدیل گفتار به متن دارای زمان‌بندی دارد. حتی با تطبیق هوشمند، برای جلوگیری از نمایش تصاویر گمراه‌کننده در خبر، هر صحنه را پیش از انتشار بازبینی کن.

## AI
اگر کلید OPENAI_API_KEY یا OPENROUTER_API_KEY قبلاً در Vercel وجود دارد، از همان به‌صورت سروری استفاده می‌شود. اگر هیچ‌کدام در Production نباشد، برنامه بدون آن‌ها کار می‌کند ولی پوشش منابع محدود می‌شود. هرگز کلید را به فایل‌های مرورگر اضافه نکن. متن نریشن برای تطبیق هوشمند به ارائه‌دهنده مدل ارسال می‌شود.
