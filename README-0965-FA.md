# RushFinder 0965 — اتصال مدل GPT Image 2.5 Flare گیسو

## علت تغییر
در تصویر ارسالی از پنل گیسو، مدل مجاز کلید `gpt-image-2.5-flare` است (مدل مستقیم، بدون پیشوند OpenRouter). نسخه 0964 به اشتباه 2.6 را صدا می‌زد و با HTTP 403 روبه‌رو می‌شد.

## این اصلاحیه چه می‌کند؟
- گزینه مدل در صفحه اینفو فقط **GPT Image 2.5 Flare** است.
- API سرور **دقیقاً** `gpt-image-2.5-flare` را به گیسو می‌فرستد.
- اگر صفحه قدیمی از کش مرورگر مدل 2.6 را بفرستد، API با پیغام «Ctrl+F5» رد می‌کند، نه اینکه درخواست پولی اشتباه بفرستد.
- مدل 2.5 با کیفیت Low برای تست اولیه انتخاب شده؛ Medium/High هم از فرم قابل انتخاب هستند.
- کلید و رمز دسترسی در متغیرهای محیطی Vercel باقی می‌مانند. **هیچ کلیدی را داخل HTML یا GitHub قرار ندهید.**
- فقط `infographic.html` و `api/avalai-image.js` تغییر می‌کنند. تدوین/Hermes/سایر APIها تغییر نمی‌کنند.

## نصب
1. ZIP را داخل پوشه اصلی GitHub پروژه RushFinder باز کنید (هم‌ردیف `infographic.html`).
2. `PUBLISH-0965-GISOO-25.cmd` را اجرا کنید.
3. در Vercel آخرین Deploy را تا وضعیت **Ready** پیگیری کنید.
4. صفحه اینفوگرافیک را با `Ctrl+F5` تازه‌سازی کنید. باید GPT Image 2.5 Flare ببینید.
5. کد دسترسی مدیر را وارد کنید و «بررسی اتصال گیسو» بزنید. **این تست مجوز ساخت تصویر را تضمین نمی‌کند.**
6. برای ساخت یک تصویر واقعی، متن را بنویسید، کیفیت Low و سپس «ساخت اینفوگرافیک» و تأیید پرامپت را انتخاب کنید. ساخت تصویر واقعی از اعتبار گیسو کم می‌کند.

## تنظیمات ضروری Vercel
- `GISOO_API_KEY` = کلید API گیسو
- `RF_INFO_ACCESS_CODE` = رمز اختصاصی دسترسی مدیر
- `GISOO_BASE_URL` (اختیاری) = `https://gisoo.pro/api/v1` یا `https://ir.gisoo.pro/api/v1`

در صورت باقی‌ماندن خطای 403، دسترسی کلید یا پروژه را در گیسو مجدداً بررسی کنید. ساخت بدون خطا با کلید واقعی از این محیط قابل تأیید نیست.
