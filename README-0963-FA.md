# RushFinder 0963 — جایگزینی چابکان با گیسو برای GPT Image 2.6

این اصلاحیه بخش اینفوگرافیک را از API قدیمی چابکان جدا می‌کند و به وب‌سرویس گیسو وصل می‌کند. از همان مسیر Vercel قبلی `api/avalai-image.js` استفاده شده تا تابع سرورلس جدیدی اضافه نشود. مدل‌های پیش‌فرض از شناسه‌های فهرست مدل‌های گیسو هستند:

- `gpt-image-2.6-sunburst`
- `gpt-image-2.6-flare`

درخواست تصویر به `POST /images/generations` فرستاده می‌شود و تصویر از `data[0].b64_json` دریافت می‌شود.

## نصب — دقیقاً به ترتیب

1. از پروژه فعلی RushFinder یک کپی پشتیبان بگیرید.
2. این ZIP را باز کنید و `infographic.html` و پوشه `api` را در ریشه پروژه GitHub RushFinder کپی کنید؛ فایل‌های هم‌نام را جایگزین کنید. فایل `api/avalai-image.js` را تغییر نام ندهید؛ این همان مسیر API موجود است.
3. فایل `PUBLISH-0963-GISOO-IMAGE.cmd` را در همان ریشه پروژه اجرا کنید. باید پیام موفقیت Git push را ببینید.
4. وارد Vercel شوید: پروژه RushFinder → Settings → Environment Variables.
5. این دو متغیر را برای **Production** اضافه کنید:
   - `GISOO_API_KEY` = کلید API که از پنل وب‌سرویس گیسو ساخته‌اید (معمولاً با `sk-gisoo-v1-` شروع می‌شود).
   - `RF_INFO_ACCESS_CODE` = یک رمز جداگانه و محرمانه برای ورود مدیر به ابزار اینفوگرافیک؛ حداقل ۲۰ نویسه تصادفی.
6. اگر سرور Vercel شما در ایران است یا از نشانی ایران استفاده می‌کنید، متغیر اختیاری زیر را هم اضافه کنید؛ در غیر این صورت لازم نیست:
   - `GISOO_BASE_URL` = `https://ir.gisoo.pro/api/v1`
   مقدار پیش‌فرض کد `https://gisoo.pro/api/v1` است.
7. Save کنید و از Deployments آخرین نسخه را Redeploy کنید. تا وضعیت **Ready** صبر کنید.
8. سایت را با `Ctrl+F5` تازه‌سازی کنید و صفحه اینفوگرافیک را باز کنید.
9. در فیلد «کد دسترسی مدیر» مقدار `RF_INFO_ACCESS_CODE` را وارد کنید؛ **اینجا API Key گیسو را وارد نکنید**.
10. «بررسی اتصال گیسو» را بزنید. این فقط فهرست مدل‌ها را می‌خواند و تصویر پولی تولید نمی‌کند.
11. مدل GPT Image 2.6 را انتخاب کنید. برای اولین آزمایش، Flare و کیفیت Low یا Medium را انتخاب کنید؛ متن خبر را وارد کنید، «ساخت اینفوگرافیک» را بزنید، پرامپت را بررسی کنید و در پنجره تأیید، ساخت واقعی را تأیید کنید.

## نکات امنیتی و هزینه

- API Key گیسو را در فایل HTML، GitHub، پیام چت یا فیلد «کد دسترسی مدیر» قرار ندهید؛ فقط در Environment Variables در Vercel ذخیره کنید.
- کلیدهای `CHABOKAN_*` و `OPENAI_API_KEY` دیگر توسط این مسیر اینفوگرافیک استفاده نمی‌شوند. آن‌ها را فقط وقتی از Vercel حذف کنید که مطمئن باشید بخش دیگری از سایت به آن‌ها وابسته نیست.
- اگر درخواست به timeout یا خطای شبکه خورد، قبل از تلاش دوباره گزارش مصرف گیسو را بررسی کنید؛ ممکن است تصویر ساخته شده باشد و پاسخ به سایت نرسیده باشد.
- گیسو خروجی تصویر را به صورت Base64 می‌دهد؛ سایت آن را روی قالب فعلی RushFinder قرار می‌دهد.
- نام‌های Sunburst و Flare و شناسه‌های مدل از فهرست مدل‌های گیسو گرفته شده‌اند. در صورت تغییر فهرست مدل‌ها، از `GET /models?type=image` شناسهٔ روز را بررسی کنید.
- ساخت تصویر واقعی در این محیط با اعتبار حساب شما اجرا نشده است؛ فقط ساختار کد و مسیر API بررسی شده است.

## اگر خطا دیدید

- `503 GISOO_API_KEY`: کلید در Vercel ثبت نشده یا Redeploy انجام نشده است.
- `503 RF_INFO_ACCESS_CODE`: رمز مدیر در Vercel ثبت نشده است.
- `403`: رمز مدیر داخل صفحه اشتباه است.
- `401`: کلید گیسو اشتباه یا غیرفعال است.
- `402`: اعتبار گیسو کافی نیست.
- `404`: شناسه مدل یا مسیر API را با فهرست مدل‌ها و مستندات گیسو تطبیق دهید.
- `429`: محدودیت درخواست یا اعتبار/سقف مصرف؛ گزارش مصرف و محدودیت کلید را بررسی کنید.
